# 0037 — Installable and useful offline: a small hand-written service worker, nothing private cached
**Status:** Accepted · 2026-10-24
**Context:** Many parishioners are on paid mobile data and unstable networks. An installable site that opens the last things they
read without a network helps them, if it never keeps what is private.
**Decision:**
1. **Manifest** per locale (names FR/EN, theme colours from tokens, existing maskable icons, `start_url` the locale home, shortcuts:
   Ce dimanche, Agenda, Prédications). `display: standalone`.
2. **Service worker `/sw.js`, hand-written (~3 KB), no Workbox** (a library would cost more than the logic). Versioned by build:
   - **precache** (install): the offline page, logo mark, icons; old caches deleted on activate;
   - **runtime:** public pages (navigations to `/fr/…` and `/en/…` only: a whitelist, so the admin and everything else are never
     seen by the worker). Pages already carry their data, so **no `/api` response is ever cached**. **Network first with a 4 s
     timeout, then the saved copy**; at most **40 pages**, oldest evicted; images from `/media` are cached up to a small count; **Save-Data** turns image caching off;
   - **never cached:** any non-GET, `/api/*` except the public JSON list below, the admin path, `/api/auth`, Mon espace, preview
     links (`apercu`, `preview`, `?t=`), registration and cancel pages, `/media` audio/PDF, and any response that is not `200`
     with `cache-control` allowing it (`private`, `no-store` are refused). A unit test feeds the worker's decision function every
     such address.
3. **Offline page** (FR/EN, illustration): lists the pages saved on this device, read from the cache.
4. **« Disponible hors ligne »:** visiting Ce dimanche, the agenda, the latest bulletin and today's meditation keeps them fresh by
   the same runtime rule; a small badge shows when a page is served from cache.
5. **Install:** no banner. A discreet « Installer l'application » in the footer, through `beforeinstallprompt` where it exists,
   short iOS instructions otherwise.
6. **Update:** a new worker takes over at once (`skipWaiting` + `clients.claim`): it holds no versioned shell that a page could
   depend on, and pages are network-first, so nothing can be stale. Old caches are deleted on activate. On `localhost` the worker
   registers only with `?sw=1`, so development never meets a stale copy.
7. **No push notifications** in this phase.
**Consequences:** `apps/web/public/sw.js` (plain file, tested by `sw-rules.test.ts` for its pure decision function), manifest routes,
a footer entry, an offline page; admin unaffected (its path is never intercepted). Real-phone offline test is Joël's.
